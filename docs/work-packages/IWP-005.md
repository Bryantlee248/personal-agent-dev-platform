# IWP-005：有人在场的三角色接力 MVP

- Roadmap：W-004
- Primary：Delivery AI
- Verifier：Independent Verification AI（Qwen 受控入口）
- 状态：BLOCKED
- 人工授权：2026-11-17 用户要求按最合适建议继续执行

## 目标

在不依赖 Paseo、Orca 或无人值守 shell 的前提下，建立可机器校验的
Architecture → Delivery → Verification → Human 接力单，让一次真实变更能按固定 SHA、
允许路径、验收命令和停止条件流转。

## 允许

- 在 `ops/handoff` 实现零依赖接力单校验器和说明。
- 增加本地端到端测试，覆盖合法接力、角色越权、路径越界、错误 SHA、秘密和非法跳转。
- 用 Qwen 受控复核入口只读审查测试证据。
- 提交、推送并使用 229 Runner 执行确定性 CI。

## 禁止

- 不自动启动开发 Agent，不授予 Qwen shell/edit/write。
- 不创建或删除真实项目 worktree，不自动合并、发布或部署。
- 不接 IM、Webhook、生产、真实数据或新增凭据。

## 验收

- 接力单包含工作项、固定 SHA、来源/目标角色、允许路径、验收命令和停止条件。
- 只允许 Architecture→Delivery→Verification→Human；Verification 没有写路径。
- 越界路径、疑似秘密、非法跳转和错误 SHA 均失败关闭。
- 本地测试、治理、converge、verify 与 229 CI 全绿。
- Qwen 只读复核给出结构化结论；该结论不替代 CI 或人工批准。

## 停止条件

- 需要无人值守 shell、系统安全降级、外部通道、真实凭据或部署授权。
- 同一实现问题连续失败两次仍无新增证据。

## 执行结果（2026-11-18）

- 第 1 轮 Qwen 只读复核发现路径根目录/`.git` 绕过、虚构 SHA、命令黑名单、秘密漏检、
  校验器自修改和边界测试不足；Delivery 在授权范围内集中修复。
- 第 2 轮 Qwen 只读复核仍发现实质缺陷：`node e2e/...` 允许列表接受 `..` 段、授权
  读取工作区 `PROJECT.json` 而非固定 SHA、Windows 路径规范化和秘密格式仍不完整。
- 已触发两轮返工上限。本轮未提交实现已撤回，未将已知不安全校验器推送到主分支。
- 详细证据：`docs/evidence/IWP-005/2026-11-18-handoff-mvp-blocked.md`。
