# IWP-011：自创建 sandbox 的事务型部署状态机

- Roadmap：W-007
- Primary：Delivery AI
- Verifier：Independent Verification AI
- 状态：ACTIVE
- 人工授权：2026-11-18 用户同意重新设计并明确批准一次性治理 bootstrap

## 目标

不实现通用部署器。只验证一个最小事务：程序在调用方提供的、已存在且为空的操作系统临时 base 目录下自行 `mkdtemp` 创建唯一 sandbox，把已验证的静态虚构制品写入其中，并通过持久事务日志完成 `PREPARED → SWITCHED → VERIFIED → COMMITTED`；故障后只恢复或清理自己创建的 sandbox。

## 输入与输出

- 输入：现有空 base 目录、现有静态 source 目录、完整小写 40 位 expected SHA、可选故障注入点。
- 禁止输入 target/current/release 路径；所有写路径均由程序在新 sandbox 内生成。
- 输出：确定性结果、sandbox 路径、最终状态、固定 SHA、事务日志和清理函数；调用方在取证后删除整个 sandbox。

## 状态机

```text
NEW → PREPARED → SWITCHED → VERIFIED → COMMITTED
          ↓          ↓          ↓
        FAILED ← RECOVERING ← interrupted/error
```

- `PREPARED` 前：完整验证 source manifest、文件集合、大小、逐文件摘要、整体摘要、expected SHA 和 `health=PASS`；不写 sandbox。
- `PREPARED`：程序创建 sandbox、独占锁、复制到 staging、验证 staging，持久化事务日志。
- `SWITCHED`：原子写 current；日志先记录切换意图，再执行切换，再记录结果。
- `VERIFIED`：只从 sandbox 内读回 current release、SHA、摘要与 health。
- `COMMITTED`：写入最终回执并删除 staging/锁；不自动删除 sandbox，便于调用方取证。
- 恢复：只接受程序返回的 sandbox；读取日志决定完成验证或删除未提交 current/release，任何歧义返回 BLOCKED，不声称回滚完成。

## 允许

- Delivery 修改 `ops/transactional-deploy`、`e2e/transactional-deploy.mjs`、对应 fixtures、IWP-011 证据和 `package.json` 测试入口。
- 使用 Node 标准库和操作系统临时目录；测试结束在 `finally` 删除 base 目录。
- 用确定性故障注入模拟 PREPARED、SWITCHED、VERIFIED 后中断，并在新调用中恢复。
- Qwen 最多两轮零普通工具调用的完整 diff复核；229 Runner 只跑确定性 CI。

## 禁止

- 不恢复或复制 IWP-010 草稿；不接受任意 target，不操作调用前已存在的业务目录。
- 不使用网络、端口、后台进程、Docker、服务、注册表、管理员权限、新依赖或凭据。
- 不写 229、ENV-PILOT、生产、真实数据或 GitHub Deployment。
- 不执行 source 内容，不自动合并、发布或发送外部消息。
- 同一 base 不允许并发事务；锁冲突失败关闭。

## 验收

- base 非空、不是临时目录子路径、是 symlink/junction 或 source/base 重叠时，在任何写入前失败。
- source 错误 SHA、摘要、额外文件、symlink、超限或 `health=FAIL` 在创建 sandbox 前失败。
- 正常路径产生 COMMITTED 日志和读回一致的 SHA/摘要；source 中的指令文本只作为字节复制。
- PREPARED/SWITCHED/VERIFIED 三个中断点均能由新调用恢复到唯一状态，且无 `.staging`、临时 current 或锁残留。
- 并发第二调用因锁失败；错误必须有稳定 code，测试断言 code 和最终目录状态，不能只断言抛错。
- 本地全部门、最多两轮 Qwen 复核和 229 五项 required checks 全绿。

## 停止条件

- 需要任意 target、既有业务目录、229、ENV-PILOT、生产、真实数据、凭据、网络或提升权限。
- 任一错误可能越出程序创建的 sandbox、破坏 source/base 既有内容或留下无法判定状态。
- 两轮独立复核后仍有实质缺陷。

## 一次性治理 bootstrap

用户明确批准仅为建立 IWP-011 临时移除 `Validate fixed-SHA PR contract`。Governance、converge、independent-verify、build-test、strict、enforce_admins、禁止 force-push/删除和会话解决保持不变。治理 PR 合并后必须立即恢复第五项，并以关闭且不合并的红灯 PR证明 `mergeStateStatus=BLOCKED`，之后才能实施。
