# IWP-004：Windows 受限执行兼容性与替代 Provider 对照

- Roadmap：W-009
- Primary：Delivery AI
- Verifier：Independent Verification AI
- 状态：ACTIVE
- 人工授权：2026-11-17 用户明确同意继续执行
- 目标环境：本地 Windows 隔离目录和临时 worktree

## 目标

确认 Paseo + Codex 的受限执行问题是否存在官方支持的安全修复路径；如果没有，
用本机已经安装且无需新凭据的候选 Agent 做同条件对照，给出执行层下一步选择依据。

## 允许

- 只读检查 Paseo、Codex 和候选 Agent 的版本、帮助、公开源码与上游 Issue。
- 在 `D:\Codex Runtime` 下建立独立测试目录，在临时 worktree 中执行无业务意义的探针任务。
- 复用本机已经配置的 provider，但不得读取或回显凭据。
- 保存版本、命令、权限模式、worktree 隔离、资源和清理证据。

## 禁止

- 不移除或削弱 Windows sandbox、安全服务、ACL、应用包身份或系统安全控制。
- 不把 `full-access` 作为长期方案，不修改默认 Codex 配置。
- 不安装未知插件，不新增付费服务或持久凭据。
- 不连接 Paseo Hub、relay、IM、Webhook、229 或生产环境。
- 不在主仓库执行候选 Agent 写入测试。

## 验收

- 上游依据能解释当前错误，并区分正式修复与不安全绕过。
- 至少一个无需新凭据的候选完成只读 shell 探针；若支持 worktree，再完成隔离写入和精确清理。
- 对照结果包含权限边界、Windows 支持、隔离能力、资源、维护成本和已知缺口。
- Independent Verification AI 复核后，Architecture AI 决定继续 Paseo、替换 provider、比较 Orca 或返回 Autoloop。

## 停止条件

- 候选要求读取凭据、关闭安全控制、修改系统 ACL、开放公网或安装不明插件。
- 同一路径连续失败两次后仍无新增证据。
- 需要新增付费账户、外部授权或真实业务数据。

## 当前结果（2026-11-17）

- Paseo + Codex 阻断与 OpenAI Codex Issue #60633 的 Windows 包身份问题一致，不采用削弱 sandbox 的绕过方式。
- TraeCLI 具备受限执行和 worktree 能力，但 headless 身份验证失败，需要用户完成正式登录后才能继续。
- 本机 Orca 只有 CodeBuddy shim，不构成独立 Orca PoC；CodeBuddy 入口还缺少 native job-object 模块。
- 证据：`docs/evidence/IWP-004/2026-11-17-windows-provider-compatibility.md`。
- 用户已配置 Qwen Code `0.27.4` 的 OpenAI 兼容自定义 Provider，并授权继续后续测试。
- Qwen 模型连通、worktree 创建、预算终止和结构化输出通过；Windows sandbox、shell 与文件写入工具面尚未通过。
- Qwen 当前只允许进入设计、分析和复核角色验证，不得承担开发写入或 CI 执行。
