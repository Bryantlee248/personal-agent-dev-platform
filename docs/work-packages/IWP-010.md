# IWP-010：本机固定 SHA 部署、健康核对与回滚演练

- Roadmap：W-007
- Primary：Delivery AI
- Verifier：Independent Verification AI
- 状态：ACTIVE
- 人工授权：2026-11-18 用户明确要求继续执行，并批准一次性治理 bootstrap 流程

## 目标

在本机临时目录中验证一个确定性的部署契约：只把已构建的静态制品按固定 SHA 发布到隔离目标，读回健康文件核对版本；健康失败时自动恢复上一个已知良好版本，并清理临时状态。

## 测试目标

- 环境：`ENV-LOCAL-TEST`，位于测试创建的临时目录，测试结束必须清理。
- 制品：测试生成的静态目录，必须包含规范化 manifest、完整小写 40 位 Git SHA 和健康载荷。
- 当前版本：以目标目录内不可变 release + 原子 current 指针表示；不启动进程、不监听端口。
- 资源：不使用 Docker、数据库、系统服务、计划任务、注册表、管理员权限或新依赖。

## 允许

- Delivery 修改 `ops/local-deploy`、`e2e/local-deploy.mjs`、`e2e/fixtures/local-deploy`、本 IWP 证据和必要的 `package.json` 脚本。
- 在操作系统临时目录下创建单次测试根目录，写入虚构制品、release、current 指针和本地回执，并在测试结束后删除。
- 测试正常部署、重复部署、SHA/制品漂移、健康失败回滚、无可回滚版本时失败关闭，以及清理。
- Qwen 在零普通工具调用下进行最多两轮只读复核；229 Runner 仅运行确定性 CI，不作为部署目标。

## 禁止

- 不写 `ENV-PILOT`、229 文件系统、生产、真实数据或用户业务目录。
- 不创建/读取凭据，不发网络请求，不监听端口，不启动后台进程，不安装软件或依赖。
- 不接受分支名、标签或短 SHA；不得从待部署目录执行代码。
- 不自动合并、发布、创建 GitHub Deployment、修改服务器或触发外部消息。
- 不在命令行、日志、回执或制品中写秘密。

## 契约

1. 输入必须给出已存在的 source、隔离 target root、expected SHA 和 health mode。
2. source manifest 的 SHA、内容摘要和 expected SHA 必须一致，任何漂移在写 current 前失败。
3. release 写入临时 staging，完成核对后再原子切换 current；重复相同 SHA 必须幂等。
4. 切换后从 target 读回健康状态和版本 SHA，不能只相信 source 或调用参数。
5. 健康失败只允许回滚到演练开始前记录的上一版本；没有上一版本则删除失败 current 并返回失败。
6. 任一失败都必须输出确定性状态、保留必要诊断并清理 staging；不得吞错或伪造成功。

## 验收

- 正常部署后 target 健康版本等于固定 SHA，并有本地回执。
- 相同 SHA 重复部署无重复副作用。
- 错误 SHA、摘要漂移、路径越界和 source 中的指令文本均失败关闭。
- 健康失败恢复上一版本；无上一版本时 target 不保留失败 current。
- 测试结束无临时目录、后台进程、端口、凭据或外部写入残留。
- lint、test、build、governance、converge、verify、本地 Qwen 只读复核与 229 CI 全部通过。

## 停止条件

- 需要写 229、ENV-PILOT、生产、真实数据、凭据或用户业务目录。
- 需要管理员权限、网络访问、后台服务、Docker、新依赖或放宽沙箱/分支保护。
- 固定 SHA、读回健康、失败回滚或清理无法确定性证明。
- 两轮独立复核后仍有实质缺陷。

## 一次性治理 bootstrap

由于 W-006 的第五项 required check 要求新 PR 引用 base 中已存在的 ACTIVE IWP，而创建 IWP-010 本身没有可引用的 ACTIVE Architecture IWP，用户明确批准只在本治理 PR 期间移除 `Validate fixed-SHA PR contract`。Governance、converge、independent-verify、build-test、strict、enforce_admins、禁止 force-push/删除和会话解决要求保持不变。治理 PR 合并后必须立即恢复第五项并用关闭且不合并的红灯 PR复验。
