# IWP-007：Verification 状态机与两轮返工上限

- Roadmap：W-005
- Primary：Delivery AI
- Verifier：Independent Verification AI（Qwen 只读）
- 状态：ACTIVE
- 人工授权：2026-11-18 用户明确指令“继续验证”

## 目标

在 W-010 固定策略接力契约之上，建立零依赖、确定性的 Verification 状态机。它只决定下一步接力方向，不启动 Agent、不执行命令。

## 输入与输出

- 输入绑定 `handoff_id`、`fixed_sha`、当前 `repair_round`、Verifier 结论和有界 findings。
- 结论只允许 `PASS / FAIL / ESCALATE`。
- `PASS`：转交 Human 审批。
- 第一次 `FAIL`：退回 Delivery，`repair_round` 变为 1。
- 第二次 `FAIL`：退回 Delivery，`repair_round` 变为 2。
- round 2 后再次 `FAIL`：转为 `ESCALATE`，禁止第三轮返工。
- 显式 `ESCALATE`：立即要求 Human 处理。

## 安全约束

- 后续事件的 `handoff_id` 与 `fixed_sha` 必须和已绑定上下文完全一致。
- 拒绝未知结论、轮次下溢/上溢、跳轮、回退或重置轮次。
- Verification 不得携带写路径或自由文本命令。
- findings 必须有数量和长度上限，并拒绝常见密钥、令牌、私钥内容。
- 状态机只返回结构化决定，不写文件、不执行命令、不创建工作树。

## 允许

- 实现 `ops/verification-state` 的纯函数状态转换和使用说明。
- 增加合法流、身份/SHA 漂移、轮次篡改、第三轮、秘密和畸形输入的失败关闭测试。
- Qwen 最多两轮只读复核；229 Runner 执行确定性 CI。

## 禁止

- 不自动启动或续接 Agent，不执行测试/命令，不自动修复。
- 不自动合并、发布、部署、发送 IM/webhook 或创建凭据。
- 不接真实数据，不扩大现有角色和写路径。
- 不修改 W-010 的冻结策略以迁就实现。

## 验收

- 所有合法转换与两轮上限可由测试复现。
- 所有身份、SHA、轮次、权限、秘密和格式异常均失败关闭。
- 两轮内独立复核无实质缺陷。
- 本地及 229 的治理、收敛、独立验证和构建测试全部通过。

## 停止条件

- 两轮独立复核后仍有实质缺陷。
- 需要自动执行、扩大权限、外部通道、部署、真实数据或新凭据。
